# ABS จริง (Maji–Prabhakaran–Rosulek) สำหรับ σ_op = σ_d (งาน B1 + B2)

วันที่ 19 พ.ย. 2026 · คน B · branch `feat/real-abs` (แตกจาก `feat/paper32-experiments` `8ff74a0`)

## ทำอะไร

- `amtp_code/amtp/core/abs.py` (ใหม่): ABS ของ **Maji, Prabhakaran, Rosulek, "Attribute-Based Signatures"
  (IACR ePrint 2008/328) Section 3.2** แบบ authority เดียว เขียนตามสมการในเปเปอร์ทุกขั้น
  - Setup: `A_0 = h_0^{a_0}`, `A_j = h_j^a`, `B_j = h_j^b`; MK = (a_0, a, b)
  - AttrGen: `K_0 = K_base^{1/a_0}`, `K_u = K_base^{1/(a+bu)}`
  - Sign: `Y = K_base^{r_0}`, `W = K_0^{r_0}`, `S_i = (K_{u(i)}^{v_i})^{r_0} (C g^μ)^{r_i}`,
    `P_j = ∏_i (A_j B_j^{u(i)})^{M_ij r_i}`, μ = H(m ‖ Υ)
  - Verify: ปฏิเสธถ้า Y = 1, `e(W, A_0) = e(Y, h_0)` และสมการต่อคอลัมน์ j = 1..t
  - pairing แบบ asymmetric `e: G1 × G2 → GT` ตามเปเปอร์ (G = G1, H = G2) บน **BN254** (ตกลงแล้ว 18 พ.ย.)
  - monotone span program สร้างแบบ Lewko–Waters จาก policy AND/OR (ค่าใน M เป็น 0, 1, −1)
  - attribute เป็น string แปลงเข้า Z_p* ด้วย hash ของ group (footnote 3 ของเปเปอร์)
- `amtp_code/amtp/core/crypto.py`: `Signer(domain=None)` เลือก scheme ตาม env **`AMTP_ABS`**
  (`ed25519` = ตัวจำลองเดิม ค่าเริ่มต้น, `mpr` = ABS จริง) และ `sig_ok` ตรวจได้ทั้งสองแบบ
  interface เหมือนเดิม (`.public`, `.sign(msg)`, `sig_ok(public, msg, sig)`) จึง **ไม่ต้องแก้ไฟล์ของคน A**
- policy ของทุก domain: `domain:Di AND role:owner` ทั้ง insert และ delete (#43); DO ได้ attribute
  `{domain:Di, role:owner}`; `AbsSigner()` หนึ่งตัว = DA ของหนึ่ง domain (Setup + AttrGen ของ domain นั้น)
- σ_d = σ_op ของคำขอ insert (ตกลงแล้ว): upload เซ็น ABS ครั้งเดียว
- `amtp_code/bench/abs_bench.py` (ใหม่): วัด Setup, AttrGen, Sign, Verify, ขนาดลายเซ็น (mean + median)
- `amtp_code/tests/test_abs.py` (ใหม่): 14 test
- `docs/prim/CLAUDE.md` (ใหม่): บันทึกงานของคน B

## เรื่องที่เจอระหว่างทำ

1. **Charm crash เมื่อเจอ identity element:** Charm แปลง byte ที่เป็นจุด all-zero กลับมาเป็น element
   ที่ไม่ใช่ identity จริง แล้วพอเอาไป pairing ตัว process **segfault** (ไม่ใช่ exception) แปลว่า CS ที่ประสงค์ร้าย
   ส่งลายเซ็นแบบนี้มาทำให้ DO validator ล้มได้ แก้: `_unpack` ปฏิเสธ element ที่เป็น all-zero
   และ element ที่อยู่ผิด group (Y, W, S_i ต้องเป็น G1; P_j ต้องเป็น G2) **ก่อน** ถึง pairing; test ครอบคลุมทุกช่อง
2. **BN254 ใน Charm ช้า:** pairing ~22 ms (PBC ใช้ BN254 แบบ type F) เทียบ MNT224 ~4 ms และ SS512 ~0.7 ms
   verify ของ policy 2 attribute ใช้ 8 pairing จึงได้ ~0.2 s ต่อครั้ง ดูตารางด้านล่าง

## สิ่งที่คน A ต้องทำต่อ

1. เพิ่ม `export AMTP_ABS=mpr` ใน `scripts/paper32_env.sh`
2. ส่งชื่อ domain เข้า `Signer(domain)` ที่ `amtp/owner.py:49` และ `bench/experiments.py:198`
   (ถ้าไม่ส่ง policy จะเป็น `domain:default AND role:owner` ขนาดและเวลาเท่ากัน แต่ชื่อ domain ใน Υ ไม่ตรง)
3. ตัดสิน issue เรื่อง curve / วิธีรายงานเวลา ABS ใน update
4. หมายเหตุ: ถ้าใช้ anchor แบบ in-process ร่วมกับ `AMTP_ABS=mpr` σ_root ก็จะเป็น ABS ด้วย (เพราะ `owner.py`
   ใช้ signer ตัวเดียวกัน) ส่วน `chain` / `chain-local` σ_root ยังเป็น ECDSA ตามที่ตกลง
