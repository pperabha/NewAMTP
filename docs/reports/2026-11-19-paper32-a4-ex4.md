## ที่ทำ
- `amtp/engine.py` `commit`: แยกเวลาใน update_ms เป็น `restructure_ms` (split / merge + relocation, Phase 3 Step 1–2),
  `posting_repair_ms` (γ, R^post, σ_w), `auth_tree_ms` (= `partition_tree_ms` + `imt_ms`), `evidence_ms`
  ใช้ทั้ง Exp 4 (split/merge overhead) และ Exp 3 ((32): "affected posting-state repair time, authentication-tree maintenance time")
- `bench/experiments.py` `Protocol.epoch`: เพิ่ม `protocol` (= update − anchor) และ breakdown ข้างบนในทุก suite ที่มี update (exp3, exp5, skewproto)
- suite ใหม่ `skewproto` (เส้น AMTP protocol เต็มของ Exp 4): เอกสาร กลุ่ม และ stream แบบ skew **ชุดเดียวกับ** `bench.ablation`
  (seed, ลำดับ skew, hot, hot-delete เหมือนกัน) แต่ละ batch = 1 epoch ของ Phase 2–3: คำขอที่เซ็น (C(d) + σ_op), CS prepare_update
  (กลุ่มของ stream = placement hint ของ CS ตาม #49), DO validate + σ_root, Root Anchor (`AMTP_ANCHOR`); การเข้ารหัสไฟล์ไม่นับ;
  ผ่าน correctness gate (`proto.check()`) ทุก skew
- `bench/ablation.py`: summary เป็น **mean** (#46) + `restructure_ms`; ทุก batch มี breakdown ใน `updates.csv`
- `scripts/paper32_env.sh`: SM_N 25000, SM_BATCHES 250, SM_B 100, SM_THETAS 64, SM_SKEWS 0,0.25,0.5,0.75,0.95, SM_RUNS 10,
  SM_HOT_DELETE 0.65, SM_VARIANTS AMTP,Static-MT,Global-MT(v), SM_QUERY_EVERY 50
- `scripts/aws_run_all.sh`: step `skewproto`, `SM_SEED` (run k ใช้ seed SM_SEED + k: แบ่ง run ข้ามเครื่องได้)
